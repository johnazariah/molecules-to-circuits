## Short Blurb

> Between a molecule and a quantum circuit lies a translation layer. This book makes it explicit: molecular data become encoded Hamiltonians, physically selected symmetry sectors, product-formula circuits and portable circuit descriptions. H₂ supplies the checked construction; a separate fixed-bond water calculation shows what a larger chemistry reference does, and does not, establish.

## Book Description

**From Molecules to Quantum Circuits** is a computational guide
to the translation layer from molecular electronic structure to logical quantum
circuits.

Core transformations are paired with executable FockMap companions, while independent PySCF scripts generate the classical chemistry references used to check them. Signs, coefficients, and intermediate Pauli strings are exposed rather than hidden behind a black-box workflow.

The guide covers six fermion-to-qubit encodings (Jordan-Wigner, Bravyi-Kitaev, Parity, balanced binary tree, balanced ternary tree, Vlasov tree), qubit tapering via diagonal and Clifford Z₂ symmetries, Trotter decomposition with CNOT cost analysis, and circuit output in OpenQASM and Q#.

Two running examples separate construction from reference chemistry: H₂ is
derived and checked from generated integrals to a JW matrix and circuit, while
H₂O supplies a PySCF FCI angular scan at fixed experimental O–H length.

## Who This Book Is For

- **Graduate students** starting in quantum chemistry simulation who need to understand the encoding layer between chemistry and circuits
- **Physicists** crossing into quantum computing who know Hamiltonians but not encodings
- **Software engineers** building quantum simulation pipelines who need the physics explained carefully
- **Lecturers** building a course module on quantum simulation who want homework exercises with verifiable answers

**What we assume:** linear algebra (vectors, matrices, eigenvalues) and introductory quantum mechanics (wavefunctions, bra-ket notation).

**What we don't assume:** chemistry, second quantisation, Pauli algebra,
fermion-to-qubit encodings, F# or measurement statistics. The unnumbered
code-reading bridge precedes Chapter 2's first factory; later constructions
receive local explanations rather than being deferred to an appendix.

## Scope and content budget

The chapter order remains The Molecule (1–3), The Machine (4), Encoding
(5–9), Tapering (10–13), Circuits (14–17), The Pipeline (18–21), and
Horizons (22–23). There are ten numbered F# labs; helper files are not
additional lab sessions.

The proposed approximately 300-page edition allocates 242 pages to chapter
content and 58 to supporting matter. This is a content-space budget, **not
an Apress-confirmed layout or a measured page count**. Fonts, margins and
blank pages are not adjusted to meet it.

`make word-count` counts whitespace-delimited tokens in the ordered sources
from `manuscript/Book.txt`, including code, tables and markup. It is a
source inventory, not a count of prose words or a pagination estimate.
Record page counts only from a named generated artifact and source commit.

## Quick Start

1. Click **Open in Codespaces** above (or clone and open in VS Code with Dev Containers)
2. Let the environment finish setting up
3. Run your first lab:
   ```bash
   dotnet fsi labs/01-first-encoding.fsx
   ```
4. Read [Reading and Running the Code](manuscript/code-reading.md) before
   the first coefficient factory. It explains complete scripts versus
   excerpts, package restoration and working directories.

The F# scripts use .NET 10 and restore the pinned NuGet package. Chemistry
reference programs separately require `requirements-data.txt`; no local
FockMap source build is required.

## Building locally

PDF and EPUB use Pandoc and the same `Book.txt` inventory; the PDF additionally
needs XeLaTeX and the fonts named in the Makefile. HTML uses MyST-based
**Jupyter Book 2**, not the incompatible Sphinx-based 1.x CLI:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
npm install --prefix _build/tools @mermaid-js/mermaid-cli@11.12.0
export MMDC="$PWD/_build/tools/node_modules/.bin/mmdc"
make manifest-check tooling-check
make sample
```

Mermaid CLI uses its installed Puppeteer browser or a discovered Playwright
Chromium installation. Set `PUPPETEER_EXECUTABLE_PATH` for an explicit
browser. `MMDC` names an executable, not a shell command.
`MMDC_NO_SANDBOX=1` is reserved for disposable CI/container environments
that require it; normal local rendering leaves the sandbox enabled.
No build repairs ownership of home-directory caches or installs global tools.

The sample is assembled from the **full book**. `Sample.txt` selects the
included bodies; the full chapter/section contents lists omitted material
with a dash instead of a page number. Omitted bodies are filtered before
diagram rendering. Missing or failed diagram renders fail the build;
valid content-addressed PNGs can be reused.

For this expansion, final PDF/sample/EPUB/HTML regeneration follows the
coordinator's immutable-pin scientific acceptance gate and content
integration. A targeted tooling check is not permission to publish.

## The FockMap Library

The code in this book uses the [FockMap](https://github.com/johnazariah/encodings)
library, published on NuGet. Labs reference it via:

```fsharp
#r "nuget: FockMap, 0.9.0"
open Encodings
open Encodings.JordanWigner
```

Release provenance: FockMap `0.9.0` was published from repository commit
`96320a56786393269fd681c67c66df88058a8b8f`; the public NuGet
`Encodings.dll` has SHA-256
`0ba8ae967ea65d4945a336c1217f8939e41feb63b6f04af617b66537717d25c3`.

FockMap feature modules are explicit rather than `AutoOpen`; Hamiltonian,
tapering, Trotter, circuit-export, and other examples open their corresponding
`Encodings.*` modules.
